# Setup with an AI assistant

Give the assistant this request:

> Read this repository's README, AGENTS.md and manual setup guide. Help me reproduce it on my own phones. Start with read-only inventory and show me which features my hardware can support. Keep all credentials and device-specific material in ignored local storage. Work in checkpoints; verify each feature on the phones and then without the PC. Ask me for account sign-in or decisions that only I can make. Do not weaken firmware checks or send messages to anyone without my authorization.

The assistant should first record the exact S2 model/build, current root/recovery options, modern Android phone Android version, installed app versions, original file hashes, ADB states and existing modifications. Use explicit `adb -s SERIAL` for every operation; ignore unrelated emulators and phones. Android's `02:00:00:00:00:00` privacy placeholder is not an actual Bluetooth address.

Read [compatibility](COMPATIBILITY.md) and [inputs](INPUTS.md), then use docs/MANUAL_SETUP.md in order. For an offline audit, never inventory or access devices; use synthetic identities and mark deployment/account/physical gates unverified. Do not silently borrow generated libraries, decoded APK directories, runtime caches or credentials from an existing working installation. Reusing installed compilers and owner-supplied original inputs is allowed when explicitly recorded. Produce a private plan with observed facts, proposed modifications, backup locations and rollback commands. Obtain authorization for the native system changes and HTTPS trust before performing them. Existing authorization can cover routine reversible continuation; do not repeatedly ask for the same permission.

The repository is a source kit, not a complete unattended installer. The native install stage deliberately requires locally generated pins, a reviewed privileged entry point and exact firmware. The assistant must resolve any missing build/runtime input and record how it was obtained. A modified APK must be built from the owner's supplied original, signed locally, and compared with the patch script's assumptions.

For optional contacts, camera video backup, AP Mobile and general notification forwarding, read [the companion feature guide](CONTACTS_CAMERA_NOTIFICATIONS.md) and [AP Mobile](AP_MOBILE.md). Obtain the owner's choices before enabling contact copying or forwarding private notifications. Preserve contact ownership markers, initial backups and camera upload receipts. Build AP Mobile only from hash-matching owner-supplied originals; do not commit decoded smali, resources or output APKs. Verify both photo and video backups in Pictures/Galaxy S2, widget binding/refresh and app labels/icons after reboot and without USB. Do not treat earlier development-phone results as fresh public-namespace device validation.

For optional battery protection, follow [CHARGING.md](CHARGING.md). Never invent an installed UID/APK path/hash, overwrite a different boot hook, publish captured firmware/configs, or fake battery readings. Build the controller from local inputs only after the Companion/call identity is consistent. Separate the development hardware tests from public-source build checks. Obtain authorization before the persistent boot change, preserve the original script and matching installer, and qualify pause/resume, screen-off wake, reboot, cable reconnect, calls, texts and Wi-Fi. Charging with Android shut down is not qualified.

For **Clear on phone**, follow the [notification-only upgrade and test](CONTACTS_CAMERA_NOTIFICATIONS.md#notification-only-upgrade). Build/install both data-service APKs with the owner's existing signer and pairing. This feature does not require replacing the calls/interface APK, changing charging identity pins, or requesting another account permission. Verify with harmless generated or owner-selected alerts: opening a detail leaves the host alert, an explicit button tap removes only its matching alert, and changed/non-clearable/excluded alerts are retained. Also dismiss a host alert directly and confirm its S2 copy disappears after the next sync; allow the documented polling delay. Check failure handling and repeat both directions unplugged. Never use a clear-all operation or dismiss unrelated personal alerts as a test; never replay a queued dismissal after reconnecting. Notification access and forwarding choices remain with the owner.

The Store library starts empty. Read docs/STORE.md and help the owner import their own APKs on the modern Android phone. Do not reproduce the original developer's app collection, scrape an archive wholesale, or treat a free download as permission to redistribute. APKs and app data never belong in a public setup commit. Register the owner's Google clients using docs/GOOGLE_ACCOUNTS.md; no shared account or developer OAuth project is provided.

Authentication stays on the owner's modern Android phone/browser. Do not put login codes or tokens in chat. The owner chooses account identity and accepts service terms. Real message tests require explicit recipients and permission. Telegram Saved Messages can be used after authorization; a Google Voice SMS test does not validate RCS.

After each checkpoint record: source revision, build hash, device installed identity, actual test performed, result, remaining limits and rollback path. Separate static inspection, build tests, synthetic tests, device observations and human audio/display confirmation. Never claim the public namespace has been tested simply because the original personal namespace worked.

Before publishing anything, inspect every tracked file, scan for local paths, names, phone numbers, MAC addresses, Wi-Fi names, account IDs, domains and secrets. Do not publish a history containing an earlier private state. Use a fresh source-only repository and a neutral commit author if requested.
